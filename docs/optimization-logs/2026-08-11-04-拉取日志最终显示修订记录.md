## 1. 背景 / 目标

用户澄清：拉取**过程中**可以完整显示 `Downloading [==>...] 1MB/2MB`、`Download complete`、`Extracting N s` 等逐层进度；**完成后**的最终消息只希望保留关键结果行，例如：

```text
✅ 拉取新镜像 - syncthing 完成 [▰▰▰▰▰▰▰▰]
⏱️ 总耗时：11.5s
 7e2749e4a0b8 Pull complete
 98a3533b5a5e Pull complete
 a0f35af530e5 Pull complete
 syncthing Pulled
```

## 2. 本轮改动（bot.py）

### 2.1 过滤逻辑作用范围修正

- 实时预览（拉取过程中）不再过滤任何日志，完整展示进度；
- 最终完成消息使用 `_PULL_FINAL_NOISE_RE` 过滤逐层进度噪音行：
  `Downloading …`（含进度条与百分比）、`Download complete`、`Extracting …`、`Verifying Checksum`、`Waiting`；
- 保留 `Pull complete`、`Pulled`、错误等关键行。

### 2.2 顺带修复：process.wait() 偶发挂起

- 压力测试发现 `process.wait()` 在子进程快速退出时偶发收不到退出通知而永久挂起，
  若不处理会卡死全局任务锁；
- 新增 `_wait_process()`：对 `wait()` 加 10s 超时，超时后 kill + 重试，
  仍拿不到退出码时按输出中是否含错误关键字推断结果；
- 超时分支的 `wait()` 同样加超时保护。

## 3. 验证结果

- 本地：`pyflakes` 无告警、`py_compile` 通过；
- 稳定性：连跑 8 次无挂起（其中多次命中竞态并走兜底路径）；
- 精确验证：按用户提供的示例输出运行，最终消息与期望完全一致。

## 4. 遗留事项 / 下次优化建议

- 退出码推断为兜底策略（仅在 asyncio 竞态丢失退出码时触发）；如后续在真实容器环境复现，可进一步排查事件循环子进程监视器配置。
