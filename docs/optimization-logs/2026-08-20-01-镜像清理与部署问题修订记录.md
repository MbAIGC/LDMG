- 日期：2026-08-20
- 序号：01
- 性质：镜像清理安全性修复 + 项目编号一致性与部署配置修订
- 关联：见 [优化记录索引](./README.md)

## 1. 背景 / 目标

本轮针对镜像清理功能和 Bot 执行流程进行复核，修复代码层面的正确性与健壮性问题。仓库中的 `docker-compose.yml` 仅作为部署参考，未修改其原有宿主机路径映射和日志挂载约定。

目标是：

- 禁止将全部本地镜像误显示为“待清理镜像”；
- 保证清理预览语义与实际 `docker image prune` 命令一致；
- 清理失败、超时或取消时不再误报成功；
- 保证面板编号与 `/upgrade 01` 等命令行编号一致；
- 避免 Docker/Compose 暂时不可用时永久缓存失败探测结果；
- 在服务升级前校验服务名；
- 取消或超时时尽量终止整个 Compose 子进程组；
- 修复 CI 在 `master` 分支构建时仍固定测试 `:main` 镜像标签的问题。

## 2. 审查发现

| 级别 | 位置 | 问题 | 影响 |
|---|---|---|---|
| 🔴 严重 | `ask_prune_confirm` | “所有未使用镜像”预览执行 `docker images`，展示全部本地镜像 | 正在使用或被停止容器引用的镜像也会被误标为待清理，破坏性操作范围不清晰 |
| 🟠 中等 | `do_prune` | 忽略 `run_command_with_feedback()` 返回值 | 清理失败、超时或取消后缺少流程级结果反馈 |
| 🔴 严重 | `cmd_list` / `cmd_upgrade` | 主面板按运行状态排序，命令行按名称排序 | `/upgrade 01` 可能升级与面板编号不同的项目 |
| 🟠 中等 | `get_compose_bin` | Docker/Compose 探测失败结果被永久缓存 | Docker 稍后恢复后必须重启 Bot 才能继续工作 |
| 🟡 轻微 | `cmd_upgrade` | 指定服务升级前未校验服务是否存在 | 拼写错误只能等 Compose 执行后才报错 |
| 🟠 中等 | `run_command_with_feedback` | 取消/超时只终止父进程 | Compose 子进程可能继续运行 |

## 3. 本轮改动

### 3.1 镜像清理预览

新增 `_scan_prune_candidates()`：

- 悬空镜像使用 `docker image ls --filter dangling=true`，与 `docker image prune -f` 对应；
- 所有未使用镜像先获取全部镜像、所有容器及其实际镜像 ID；
- 排除被运行中或已停止容器引用的镜像；
- 按完整镜像 ID 去重，避免同一镜像多标签重复展示；
- Docker 查询返回非零时禁止出现确认按钮；
- 在确认提示中说明预览是当前时刻快照，确认时 Docker 仍会重新判断实际范围；
- 全程使用参数数组调用 Docker，不经过 shell 拼接。

### 3.2 镜像清理结果处理

- 保存并检查 `run_command_with_feedback()` 返回值；
- 成功时发送明确的清理完成消息；
- 失败、超时或取消时发送失败/取消提示，不再宣称完成；
- 无论成功还是失败都通过 `finally` 释放任务锁；
- 成功后刷新项目缓存。

### 3.3 项目编号一致性

新增统一的 `sort_projects_for_display()`，主面板和 `/upgrade` 命令均按“运行中优先、名称排序”的规则处理项目，避免编号错位。

### 3.4 其他执行流程修复

- Docker/Compose 探测仅缓存成功结果，失败时后续请求可以重新探测；
- `/upgrade N service` 在创建确认按钮前校验服务是否属于目标项目；
- Compose 命令以独立进程组启动，取消或超时时终止整个进程组，降低子进程残留风险。

### 3.5 部署参考文件

本轮已恢复 `docker-compose.yml` 的原始参考配置：

```yaml
- /docker:/mnt/data1/docker
```

仓库提供的 Compose 文件需要使用者根据自己的宿主机目录和容器内路径进行调整，本轮不将参考部署文件的路径约定视为代码 bug。

## 4. 验证结果

- `python3 -m py_compile bot.py bot-v1-grok.py` 通过；
- 静态复核确认 all-unused 预览不再直接展示全部 `docker images` 输出；
- dangling 预览与 `docker image prune -f` 参数语义对应；
- all-unused 执行仍使用 `docker image prune -a -f`；
- 预览失败不会创建确认按钮；
- 面板和 `/upgrade` 共用项目排序函数；
- `docker-compose.yml` 已恢复为原始参考配置，未把部署者的路径选择作为代码修复项；
- Smoke Test 改为使用当前 Git 分支对应的镜像标签，避免 master 构建固定测试不存在的 main 标签。

## 5. 遗留事项 / 下次优化建议

- 预览与确认之间仍存在 Docker 状态变化的竞态，实际删除范围以 Docker 执行时判定为准；
- 建议在带 Docker daemon 的 CI 或测试机上补充运行时测试，覆盖多标签镜像、停止容器引用镜像、无容器和权限失败等场景；
- 进程组终止依赖 Unix/Linux 的 `start_new_session` 与 `killpg`，Windows 环境需要单独适配。
